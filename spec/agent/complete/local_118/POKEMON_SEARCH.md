# ポケモン検索の利用経路再構成 仕様書

## 1. 概要

### 1.1 目的

「検索」カテゴリを「ポケモン検索」「孵化検索」に整理し、ポケモン検索内で「個体値から探す」「色違い・性格から探す」を選べるようにする。利用者が MT Seed / LCG Seed の違いを理解したり、外部で Seed を準備したりせずに、目的に合った検索へ進めることを目指す。

実装・検証完了（2026-09-06）。検索アルゴリズム、CPU / GPU の実行経路、WASM API と性能測定は [POKEMON_SEARCH_ENGINE.md](../local_119/POKEMON_SEARCH_ENGINE.md) に記載する。

### 1.2 用語定義

| 用語 | 定義 |
|------|------|
| ポケモン検索 | 孵化以外のポケモンを対象に、入手条件に合う起動日時・起動条件を探す入口 |
| 個体値から探す | 個体値条件に対応する候補を先に絞り、その候補になる起動日時を探す利用経路 |
| 色違い・性格から探す | 個体値を条件にせず、色違い・性格・出現種・性別・特性・レベルに一致する個体と起動日時を探す利用経路。名称は代表的な条件を示すもので、条件を色違い・性格だけに限定しない |
| 起動条件 | Timer0、VCount、キー入力など、日時とともに初期 Seed を決定する条件 |
| MT Seed | 個体値側の乱数生成に用いる Seed。設計上の用語であり、検索方式の選択肢には使わない |
| LCG Seed | 性格値などの生成に用いる乱数の Seed。検索結果の詳細や既存の直接入力では引き続き扱う |

### 1.3 背景・問題（着手時点）

本質的な問題は、個体値を不問として、色違い・性格・出現するポケモンの種別などの条件を満たす起動日時と消費位置を探索する機能が提供されていないことである。色違いだけ、特定の種族と性格だけ、といった要求に対しても、目標 MT Seed の指定を前提とせず検索できる必要がある。

現在の「起動時刻検索」は指定 MT Seed の一致を判定する。個体生成リストには色違い・性格・種族などのフィルターがあるが、渡された Seed を列挙する機能であり、日時範囲の探索とは接続されていない。

[徘徊乱数の参考記事](https://milk4724.hatenablog.com/entry/20260910/00000000)のランダム MT Seed を使う手順は、この機能不足を補う利用例である。外部ツールの貼付操作を減らすことだけでなく、指定した日時・消費範囲をポケモンの条件で探索できることを要件とする。

検索の入口は、個体値を起点とする経路と、個体値以外の条件を起点とする経路に整理する。「起動時刻検索」はどちらにも当てはまるため、片方だけのタブ名には用いない。

### 1.4 期待効果

| 項目 | 期待効果 |
|------|----------|
| 入口の選択 | 「ポケモン検索／孵化検索」と、目的に応じた検索方式の名称から選べる |
| 個体値不問の検索 | 外部のランダム MT Seed 生成・貼付を不要にする |
| 一致個体の確認 | 色違い・性格から探す経路では、個体と起動条件を検索結果でまとめて確認できる |
| 個体値を狙う検索 | 既存のテンプレート・直接入力・MT Seed 検索からの転記を「個体値から探す」の入口で利用できる |

### 1.5 着手条件

以下の確定事項に従って実装した。新方式の転記は結果詳細から選択した 1 件を対象とし、起動条件と対象・生成条件を渡す。転記先のフィルター・消費範囲は変更しない。対応エンカウントは固定・野生・徘徊を含む既存の個体生成リストの対応範囲を基本とする。個体値側は既存の起動時刻検索を位置付け直す範囲で確定する。

検索処理・実行経路・WASM API と検証条件は技術設計書に記載する。新しい検索は CPU の直接探索のみで実装し、既存機能の GPU 経路は維持する。CPU 検索の性能は技術設計書 5.2 の測定で確認した。

## 3. 設計方針

### 3.1 決定事項

- 「検索」カテゴリの入口を「ポケモン検索」「孵化検索」にする。
- ポケモン検索内の選択肢は「個体値から探す」「色違い・性格から探す」とする。
- 色違い・性格から探す経路では、目標 MT Seed の事前準備を求めない。
- 個体値不問で、色違い・性格・出現種・性別・特性・レベルの条件を満たす候補を日時範囲から探索する。

孵化検索内には「個体値から探す」「色違い・性格から探す」の二択を設けない。既存の孵化検索経路を維持する。

検索方式の選択は、既存の起動時刻検索画面の MT Seed セクションを置き換える位置に置く。「個体値から探す」「色違い・性格から探す」を横並びのタブで表示し、その直下の入力内容を切り替える。上位タブを検索方式ごとに増やさない。初回は「個体値から探す」を選択し、以後は最後に選択した方式を保存・復元する。

既存の起動時刻検索を「個体値から探す」に位置付け、テンプレート選択・MT Seed 直接入力・既存の MT Seed 検索からの転記を維持する。個体値入力は既存の MT Seed 検索で行う。

### 3.2 技術設計との境界

日時と消費位置の直接探索、条件判定、バッチの中断・再開、結果型、Worker 接続は技術設計書で定義する。GPU は「個体値から探す」の既存経路では維持し、新経路は CPU のみで実装する。新経路には GPU 切替を表示せず、既存の選択状態を流用しない。GPU 対抗案は今回の不採用理由を技術設計書に記録する。

## 4. 実装仕様

本節は実装した画面と利用経路を定義する。API と検索器の内部構造は技術設計書に従う。

### 4.1 画面構成

```text
検索
├─ ポケモン検索
│  ├─ 個体値から探す
│  └─ 色違い・性格から探す
└─ 孵化検索
```

「起動時刻検索」は独立したタブ名としては使わず、起動日時を探す操作の説明に用いる。内部の機能 ID `datetime-search` と既存のディレクトリ名は維持する。新方式の実装は `features/pokemon-search` に置く。

画面の配置は既存の `DatetimeSearchPage` と `FeaturePageLayout` を踏襲する。PC は左の条件入力・右の結果、モバイルは条件入力の下に結果を置き、検索操作は既存の下部固定バーを使う。

```text
ポケモン検索
条件入力欄
  検索開始／キャンセル・進捗（PC）
  日付・時刻・キー入力の範囲（既存の位置）
  検索方式（既存 MT Seed セクションの位置）
    [ 個体値から探す | 色違い・性格から探す ]
    選択した方式の入力欄
結果欄（PC は右、モバイルは条件入力の下）
  選択した方式の結果・詳細・出力
```

検索方式の選択には既存の `Tabs` / `TabsList` / `TabsTrigger` / `TabsContent` を使う。二つのラベルを常時表示し、モバイルでも名称を省略しない。幅が不足する場合はタブ内の折り返しで収める。選択状態を示し、キーボードで選択できるようにする。検索中は両方のタブを無効にする。

| 表示位置 | 個体値から探す | 色違い・性格から探す |
|----------|----------------|----------------------|
| 切替より上の日時・キー入力 | 既存の入力部品を表示 | 同じ入力部品を表示 |
| タブ直下の入力 | MT Seed 見出し、テンプレートボタン、直接入力欄 | 対象・生成条件、消費範囲、絞り込み条件の順に表示 |
| 検索操作・進捗 | 既存の日時検索に接続。GPU 選択を表示 | 新しい CPU 検索に接続。GPU 選択は非表示 |
| 結果欄 | 既存の起動条件の一覧・詳細・出力 | 一致個体と起動条件の一覧・詳細・出力 |

色違い・性格側の対象・生成条件には、既存ポケモンリストの対象エンカウント、場所・スロット等の対象設定、先頭特性などを配置する。消費範囲には開始オフセット・最大消費数を置く。絞り込みには色違い・性格・出現種・性別・特性・レベルだけを配置し、個体値・めざめるパワー・実数値の条件は表示しない。入力部品は既存ポケモンリストから再利用するが、Seed 入力欄は持ち込まない。

切替部品を置く場所は MT Seed セクションだが、選択状態は画面全体の検索方式を決める。検索ボタン、入力検証、件数見積もり、結果・詳細・出力も選択した方式に接続する。非選択側の入力エラーで検索を禁止しない。結果の空表示も方式ごとに案内し、色違い・性格側で MT Seed の入力を要求しない。

日時・キー入力は配置と部品が共通でも、値は 4.5 のとおり方式別に保持する。切替時には選択先の日時・キー入力と結果を復元する。切替時の値のコピーや自動検索は行わない。

### 4.2 個体値から探す

既存の起動時刻検索を「個体値から探す」に位置付ける。目標 MT Seed を指定し、その Seed になる起動日時・起動条件を検索する既存機能を維持する。

目標 MT Seed の指定方法は、テンプレート選択、直接入力、既存の「MT Seed 検索」からの転記の三つを維持する。個体値条件を入力して MT Seed を求める操作は、引き続き既存の「MT Seed 検索」で行う。本変更には個体値入力画面の統合を含めない。

日時・キー範囲を指定して検索し、結果を既存の個体生成リストへ転記して確認する。日時検索結果は起動日時・起動条件の候補であり、色違い・性格の一致を保証しない。色違い・性格の追加絞り込みは個体生成リストで行い、本経路への一括検索の追加は本変更に含めない。

### 4.3 色違い・性格から探す

1. プロファイルの本体・ソフト情報を参照し、対象ポケモン・エンカウント条件を設定する。色違いを指定する場合は TID/SID を必要とする。
2. 色違いの種類、性格、出現種、性別、特性、レベル範囲と、開始オフセット・最大消費数を設定する。個体値・めざめるパワー・実ステータスは検索条件にしない。
3. 日付・時刻・キー入力の範囲を設定して検索する。
4. 条件に一致した個体と、その個体に対応する起動日時・起動条件・消費数を確認する。
5. 候補を選び、個体生成リストなどで前後の個体・針を確認する。

色違い・性格の両方を必須にはしない。出現種のみ、性別のみなど、他の条件からも検索できるようにする。条件同士は AND、性格・種族の複数選択内は OR とする。全条件未指定の扱いと結果件数の事前警告は技術設計書に記載する。

追加する絞り込みは性別・特性・レベルの三つとする。性別は生成結果の性別、特性は既存の特性スロット、レベルは上下限を含む範囲で判定し、上下限を同じ値にすれば単一レベルを指定できる。特性条件はプレイヤー側の先頭特性設定と区別する。先頭特性は生成の前提設定であり、検索対象の特性を指定するものではない。

絞り込みは `PokemonSearchFilterForm`（新規の専用フォーム）で入力する。既存の `PokemonFilterForm` 全体は流用せず、色違い・性格・種族・性別・特性・レベルの入力部品を組み合わせる。種族選択は既存フォーム内の部品を共通化して利用する。フォームの値は `PokemonDatetimeSearchFilter` とし、非対象の条件を隠して保持する方式にはしない。

| 入力 | 操作 |
|------|------|
| 色違い | 指定なし・色違い全体・星・ひし形を選択 |
| 性格・出現種 | 複数選択。空の選択は指定なし |
| 性別・特性 | 既存の選択部品を使用し、指定なしで解除 |
| レベル | 上下限を入力。同値は単一レベル。指定なしで解除 |

フィルター全体の有効／無効スイッチは設けない。既存の個体生成・孵化フィルターと同じ `RotateCcw` アイコンのリセットボタンで、六条件だけを指定なしに戻す。ボタンの読み上げラベルは「フィルターリセット」とする。対象・生成条件、消費範囲、日時・キー入力は変更しない。検索中は入力とリセットを無効にする。

対象変更時の処理は既存の `PokemonParamsForm` とポケモン生成画面に合わせる。カテゴリ・エンカウント変更時の対象選択の初期化、場所・固定対象に応じたスロット取得、候補一覧の更新を共通の処理で行う。既存の `PokemonFilterForm` は種族・性格・色違い・性別・特性・レベルを対象変更時に自動解除していないため、新フォームでも保持する。候補一覧から外れた種族条件も自動削除せず、条件不一致なら結果なしとなる。既存にある持ち物・出現結果・特殊発生の非表示条件の調整は、新フォームでは対象条件自体を持たないため不要である。

色違い条件を指定した場合、共通設定の TID / SID のいずれかが未設定なら検索開始を止め、不足している ID の設定を案内する。0 は有効な ID とし、未設定と区別する。色違い条件が指定なしなら ID 未設定でも検索でき、性格・レベル・出現種などの条件を独立して利用できる。確認ダイアログを開く前に検証し、確認後の実行には検証済みの検索条件を使用する。未設定 ID の計算経路は技術設計書に従う。

PID の直接入力・完全一致検索、持ち物・移動エンカウント判定・特殊エンカウント発生の任意フィルターは本変更に含めない。釣り失敗・アイテム結果を除外してポケモンだけを返すことは、任意の絞り込みではなく検索結果の基本条件とする。

対応エンカウントは、固定・野生・徘徊を含む既存の個体生成リストの対応範囲を基本とする。既存のソフト別・エンカウント別の制約を引き継ぐ。`HiddenGrotto` は共通生成器が未対応のため、新方式では非対応を案内して開始を止める。孵化は既存の孵化検索を使う。

初期の具体例は、参考記事の BW 徘徊ポケモンを、個体値不問・任意の性格・色違い・開始オフセット 6／最大消費数 30 で探す操作とする。この数値は記事の利用例であり、機能共通の既定値や必要な操作回数として固定しない。

### 4.4 結果と後続の確認

色違い・性格から探す結果一覧は、詳細操作、起動日時、消費数、ポケモン、性格、色違い種別、性別、特性、レベル、個体値／実数値（H/A/B/C/D/S）、Timer0、キー入力の順に配置する。既存の個体列を再利用し、起動日時・Timer0・キー入力の列を追加する。初期ソートは起動日時の昇順、同日時内は消費数の昇順とする。並べ替えには表示文字列ではなく日時・消費数の値を使う。

個体値／実数値は既存ポケモンリストと同じ表示切替を設け、表示・出力対象とする。詳細画面には一覧の情報に加えて PID、LCG Seed、MT Seed、VCount、針など既存の個体生成結果の詳細を表示する。PC / モバイルとも同じ列・詳細の意味を保ち、横幅不足は既存テーブルのスクロールで扱う。CSV / JSON にも起動条件・消費数・個体情報を含める。

同じ起動日時・起動条件でも、複数の消費位置が一致した場合は区別して扱う。消費数の表示は既存の個体生成リストと意味を揃え、実際に行うレポート・ペラップの回数と混同させない。

新方式の結果詳細に「個体生成リストで確認」を設け、選択した 1 件の起動条件と対象・生成条件を転記して個体生成リストへ移動する。新方式に「全結果を個体生成リストに転記」は設けない。既に一致個体の生成・絞り込み・表示を行っており、転記の目的は選んだ候補の前後の個体や針を確認することだからである。「個体値から探す」の既存の全結果転記は維持する。

| 転記項目 | 扱い |
|----------|------|
| 起動条件 | 選択した結果の `SeedOrigin::Startup` を 1 件渡す。既存の詳細転記と同様、転記先の現在の本体設定・Timer0 / VCount 範囲で、渡された日時・キー入力から Seed 候補を再計算する |
| 対象・生成条件 | 検索時のエンカウント種別、場所・固定対象の選択、遭遇方法、スロット構成、先頭特性を一式渡す |
| フィルター | 転記しない。転記先の既存設定を保持する |
| 消費範囲 | 転記しない。転記先の開始オフセット・最大消費数を保持する |

対象・生成条件は、転記時点の編集中フォームではなく、選択した結果に対応する検索開始時の設定から取得する。既存の生成フォームでは消費範囲も `encounterParams` に含まれるため、オブジェクト全体を上書きせず、転記先の `genConfig` を保持して対象・生成条件を反映する。

本体・ソフト・起動設定・トレーナー情報は転記先の現在の共通設定を使用する。転記で検索時の共通設定に戻す機能は設けない。選択する検索結果は 1 件でも、現在の Timer0 / VCount 範囲による再計算で Seed 候補が複数になることは許容する。

候補の消費位置を含める設定や前後の個体を確認するための条件変更はユーザーが転記先で行う。フィルターの自動解除や消費範囲の自動変更を伴う周辺確認専用操作は設けない。転記だけでは生成を自動開始せず、転記先で条件を確認して実行する。

個体値不問は検索条件の扱いを示し、結果の個体値・実数値を非表示にする意味ではない。値は既存の個体生成リストと同じ生成・計算条件に基づいて表示する。参考記事の殿堂入りによる徘徊再生成など、その計算条件と実機の MT 消費が一致しない場合まで捕獲時の値を保証するものではない。

### 4.5 切替と既存経路の継続

方式ごとに入力・結果を分けて保持し、切替時に他方の条件を混入させない。日時・キー範囲も方式別に保持する。本体・ソフト・トレーナー情報は既存の共通設定を参照する。入力と選択方式は保存・復元し、結果は同一セッション内の切替で保持するが永続化しない。初回は IV モード。新 Store は `feature:pokemon-search` version 1 を使用し、既存 `datetime-search` の保存形式を変更しない。新方式の日時初期値は既存と同じ 2000～2099、生成条件の初期値は既存 `DEFAULT_ENCOUNTER_PARAMS` とする。

検索中の方式切替は不可とする。切り替える場合は検索の完了またはキャンセルを待つ。検索を開始する際は、その方式の以前の結果を置き換える。

既存の MT Seed 検索からの転記は「ポケモン検索」の「個体値から探す」へ到達させる。既存の Seed 入力・保存データ・結果の転記経路への影響を確認する。公開済みの永続化形式を変更する場合は、保存名の変更またはバージョンと移行処理を用いる。

### 4.6 性能要件・制約

|------|----------------|
