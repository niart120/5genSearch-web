# PokemonGenerator のフィルター統合と個体値遅延計算 設計書

## 1. 概要

### 1.1 目的

`PokemonGenerator` にフィルター判定を統合し、個体値に依存しない条件で候補を絞ってから、必要な個体値・実数値を計算する。既存の個体生成リストと [local_119 の日時検索](../../wip/local_119/POKEMON_SEARCH_ENGINE.md) は同じ生成器を使用する。

型名は `PokemonGenerator`、一位置を処理するメソッドは `generate_next()`、戻り値は `Option<GeneratedPokemonData>` とする。生成・判定・個体値計算は Rust 内部で完結する。本書の生成器改修・回帰検証は 2026-09-06 に完了した。

### 1.2 用語定義

| 用語 | 定義 |
|------|------|
| 候補 | 一つの消費位置から生成した `RawPokemonData`。個体値・実数値を持たない内部データ |
| 個体値非依存条件 | 性格・性別・特性・色違い・種族・レベル・持ち物・エンカウント結果・特殊エンカウント発生の条件 |
| 個体値条件 | 個体値範囲と、個体値から求めるめざめるパワーの条件 |
| 実数値条件 | 個体値・種族・性格・レベルから算出したステータスに対する条件 |
| `rng_ivs` | 一つの生成器が処理する初期 Seed と生成条件に対応する六つの個体値。未計算時は `None` |

### 1.3 背景・問題

現在は `PokemonGenerator::new()` で MT を初期化して個体値を求め、各候補に個体値・実数値を付けてから、一括生成の呼び出し元がフィルターを適用している。この順序では、色違いなどの条件に一件も一致しない Seed にも MT 計算が発生する。

個体値を検索条件に使わなくても、結果の表示・出力には個体値・実数値が必要である。生成器内で計算を遅延し、条件を通過した候補だけについて完成した結果を作る。

### 1.4 期待効果

| 項目 | 期待効果 |
|------|----------|
| MT 計算 | 個体値非依存条件を一件も通過しない生成器では 0 回、通過する生成器では最大 1 回 |
| 実数値計算 | 個体値非依存条件・個体値条件を通過した候補だけ計算する |
| 共通化 | 既存リストと日時検索が同じ生成・フィルター処理を使う |
| 出力 | 指定した有限範囲に対して、現行の生成後フィルター適用と同じ結果・順序を得る |
| TS 境界 | TS は完成した一致個体だけを受け取る。候補ごとの往復を行わない |

### 1.5 着手条件・実施順序

本書の実装・回帰検証を `local_119` の日時検索器に先行させる。変更前の結果を固定したテストを用意し、フィルター段階の抽出、生成器の変更、一括生成の接続変更の順に実施する。日時検索の公開 API・Worker・UI は `local_119` で実装する。

## 3. 設計方針

### 3.1 一つの生成器内で段階的に判定する

```text
PokemonGenerator::new
  → 起動時消費・LCG 列挙位置を設定
  → rng_ivs = None

generate_next（消費位置を一つ処理）
  → RawPokemonData と付加情報を生成
  → 列挙位置を一つ進める
  → 個体値非依存条件を判定。不一致なら None
  → rng_ivs が未計算なら MT から計算し保持
  → 個体値条件を判定。不一致なら None
  → GeneratedPokemonData を構築し実数値を計算
  → 実数値条件を判定。不一致なら None
  → Some(完成した個体)
```

既存リストも新しい日時検索もこの順序を使う。保持すべき互換性は結果の値・順序・条件の意味であり、内部の計算順序は変更する。

### 3.2 一回の呼び出しと終了の意味

`generate_next()` は一つの消費位置だけを処理する。`None` はその位置から返す結果がないことを示し、列挙終了を意味しない。

`take(count)` は `count` 回の生成試行から `Some` だけを集める。`count` 件の一致を得るまで反復しない。終了は呼び出し側の指定範囲・試行回数で管理し、`None` で打ち切る標準 `Iterator` の実装にはしない。

### 3.3 所有する状態

Seed、生成設定、列挙位置、フィルター、個体値キャッシュは `PokemonGenerator` が所有する。フィルターや設定を呼び出し途中で外から変更しない。一括生成と日時検索は生成器の呼び出し回数・バッチ境界を管理するだけとする。

## 4. 実装仕様

### 4.1 コンストラクターと保持フィールド

Rust 内部のコンストラクターを次の形にする。

```rust
pub fn new(
    source: SeedOrigin,
    params: &PokemonGenerationParams,
    config: &GenerationConfig,
    filter: Option<&PokemonFilter>,
) -> Result<Self, String>;
```

初期 Seed は `source.base_seed()` を唯一の取得元とする。生成器は `source` を所有し、生成設定とフィルターを複製して保持する。内部呼び出し元とテスト・ベンチマークを更新する。公開 WASM 関数の引数を変更する必要はない。

`rng_ivs` を `Option<Ivs>` に変更し、作成時は `None` とする。`new()` は従来の起動時消費と LCG 開始位置を設定するが、`generate_rng_ivs_with_offset()` は呼ばない。

### 4.2 個体値の遅延計算

個体値の取得は private な `ensure_rng_ivs(&mut self) -> Ivs` に集約する。具体的な処理は次のとおり。

```rust
fn ensure_rng_ivs(&mut self) -> Ivs {
    if let Some(ivs) = self.rng_ivs {
        return ivs;
    }

    let mt_seed = self.source.base_seed().derive_mt_seed();
    let offset = calculate_mt_offset(self.config.version, self.params.encounter_type);
    let is_roamer = self.params.encounter_type == EncounterType::Roamer;
    let ivs = generate_rng_ivs_with_offset(mt_seed, offset, is_roamer);
    self.rng_ivs = Some(ivs);
    ivs
}
```

常に初期 Seed を使い、列挙中の `self.lcg.current_seed()` から MT Seed を導出しない。MT オフセットと徘徊用の個体値並び替えは既存の関数に委譲する。

状態遷移は `None → Some(ivs)` の一方向だけとする。生成器が存在する間はリセットしない。別の初期 Seed・生成条件は別の生成器として扱う。保持するのは個体値のみであり、MT の状態配列や Seed 横断キャッシュは持たない。

個体値非依存条件を最初に通過した時点で計算する。個体値条件で不一致でも計算済み個体値を保持し、後続の呼び出しで再利用する。バッチが切れても同じ生成器を保持すれば再計算は発生しない。

個体値・実数値を表示するため、フィルターなしでも実際に結果を構築する際に計算する。未計算状態を公開結果の不明値・仮の 0 として返さない。

### 4.3 条件判定の分割

既存の `PokemonFilter` は公開形式を変えず、内部の評価を次の三段階へ分ける。

| 段階 | 条件 | 必要な値 |
|------|------|----------|
| 個体値非依存 | 性格・性別・特性・色違い・種族・レベル・持ち物・エンカウント結果・特殊エンカウント発生 | `RawPokemonData` と既存の付加情報 |
| 個体値 | 個体値範囲・めざめるパワー | 計算済み `Ivs` |
| 実数値 | ステータスの指定 | 完成した個体の `core.stats` |

比較処理は `types/filter.rs` に集約する。個体値非依存段階が必要とする値だけを持つ crate 内部の参照用入力を定義し、候補と完成した個体の両方から同じ比較処理を呼べるようにする。候補側からの変換は生成側に置き、`types/` から `generation/` に依存させない。

`PokemonFilter::matches()` は完成済み個体に対する判定として維持し、同じ比較処理と既存の `IvFilter` / `StatsFilter` 判定を使う。候補を判定するために仮の `GeneratedPokemonData` を作らない。比較式を新旧の入口に重複して記述しない。

未指定・空配列、選択肢内 OR・条件間 AND、範囲境界、不明個体値・不明ステータスの既存判定を維持する。短絡評価の順序は変わるが、判定結果は変えない。フィルター判定は乱数を消費しない。

`local_119` は六条件から `PokemonFilter` を組み立て、個体値・実数値・持ち物・発生条件は未指定、出現結果は `PokemonOnly` として生成器に渡す。新検索固有の任意条件を共通生成器へ追加しない。

### 4.4 乱数列挙と結果構築

現在位置の針・消費数を取得し、列挙用 LCG の複製で既存の固定／野生の生成関数を呼ぶ。生成処理内の乱数消費を列挙用 LCG に伝播させない。

列挙用 LCG と `current_advance` は一試行ごとに一つ進める。フィルターによる早期 return は、その更新後に行う。生成できなかった場合も現行と同じ位置更新・`None` の扱いを維持する。

アイテム・釣り失敗を共通生成器で一律除外しない。既存リストではフィルターに従って返し、新検索では `PokemonOnly` により MT 計算前に除外する。

個体値条件を通過した候補は、既存の `GeneratedPokemonData::from_raw()` で結果を構築する。実数値は個体値だけでなく種族・性格・レベルに依存するため、個体ごとに既存の努力値 0 の計算を行う。針・生成元・付加情報はその位置で得た値を使う。

### 4.5 一括生成と日時検索の接続

`generate_pokemon_for_seed()` は `PokemonGenerator::new()` にフィルターを渡し、`take(max_advance - user_offset)` の結果を返す。ポケモンの `apply_pokemon_filter()` による後段の再判定は削除する。孵化の一括判定は維持する。

日時検索も同じ生成器を使い、`generate_next()` の呼び出し回数を処理件数として数える。`Some` を収集し、`None` でも探索を継続する。一致件数とは別に試行回数の上限で制御を返す。生成器の消費位置と `rng_ivs` はバッチ間で保持する。

一括生成・日時検索とも、開始位置を含み終了位置を含まない範囲を呼び出し側が管理する。同値の範囲では呼び出しを行わず、MT 計算も行わない。不正範囲の検証と実行時の終了判定を、フィルター不一致の `None` と混同しない。

### 4.6 TS / WASM 境界

`generate_pokemon_list()` の公開引数・戻り値と、`GeneratedPokemonData` / `PokemonFilter` の公開形式は維持する。内部コンストラクターの変更は Rust の呼び出し元へ反映する。

TS は検索条件を渡し、個体値・実数値まで完成した一致結果を受け取る。候補型・個体値キャッシュ・個体値取得メソッドは WASM に公開しない。新しい日時検索の公開 API は `local_119` で扱う。

## 5. テスト方針

変更前の出力を固定したケースと、既存の既知 Seed テストを使う。変更後の同じ比較処理を二度呼んだだけの検証で済ませない。

| 分類 | 検証内容 |
|------|----------|
| 生成結果の回帰 | 固定・野生・徘徊、先頭特性、起動設定について全結果フィールド・順序が同じ |
| フィルターの回帰 | 六条件に加え、既存の個体値・めざめるパワー・実数値・持ち物・発生条件を含む結果が同じ |
| 遅延初期化 | `new()` 直後と非依存条件で全件不一致の場合は未計算。最初の通過で計算し、その後は再利用する |
| 再利用と初期 Seed | 先頭で不一致が続いた後の一致でも初期 Seed の個体値を使う。バッチ相当の呼び出し分割で結果・計算回数が変わらない |
| 個体値条件での不一致 | 非依存条件通過後に個体値で落ちても、MT を次の試行で再計算しない |
| 実数値 | 同じ個体値でも候補の種族・性格・レベルに応じて算出する |
| `None` と列挙 | 不一致の次の位置で一致できる。`take(count)` は不一致を含む指定試行回数で終了する |
| 公開境界 | 既存 WASM 型・一括生成と TS 統合テストが維持され、内部状態が露出しない |
| 共通処理の影響 | 孵化の既存条件判定・出力が維持される |

MT 計算回数はテスト専用の局所的な計測で検証し、公開の計測 API やグローバル可変カウンターを追加しない。

| 性能測定 | 比較条件 |
|----------|----------|
| 既存リスト | フィルターなし・個体値条件・色違い条件で変更前後を比較 |
| 日時検索向けの生成 | 一致なし・少数一致・全件一致、複数の Seed 数・消費範囲を比較 |
| 記録する費用 | MT 計算回数、生成試行数、実数値計算数、総実行時間、ピークメモリー |

### 5.1 実装判断と検証結果 (2026-09-06)

- `CoreFilterInput` / `PokemonFilterInput` を crate 内部だけに定義し、候補からの変換は生成側に置いた。孵化と完成済み個体も共通の比較処理を使う。
- 逆転範囲・起動時消費の加算オーバーフロー・空スロット・固定の複数スロットを生成器の初期化エラーにした。正常な有限範囲の出力契約は維持する。
- `cargo test -p wasm-pkg`: 単体 341 件、統合 8 件成功。計測用 1 件は別途 release で実行。初期 Seed の利用、バッチをまたぐ MT 1 回、個体値不一致時の実数値 0 回、試行数と一致件数の区別を局所カウンターで確認した。
- `pnpm test:run`: 122 ファイル・1473 件成功、4 件スキップ。WASM 再ビルド後にポケモン・孵化・並列生成・針のブラウザー統合 14 件を再実行し成功。

### 5.2 性能測定

Windows のネイティブ release、Criterion。`cargo bench -p wasm-pkg --bench generator -- pokemon_filter_pipeline` で生成後判定と段階的判定を同じ Seed・位置で比較した。生成後判定は現行生成器のフィルターなし出力に後段で条件を適用する比較実装であり、旧バイナリー全体の比較ではない。単位は µs、区間推定の中央値。

| 100 × 24 | 一致なし | 218.36 | 42.89 |
| 100 × 24 | 色違い | 217.80 | 42.62 |
