# 上位条件に依存する下位条件の整合性 仕様書

## 1. 概要

### 1.1 目的

バージョン、リージョン、遭遇種別、場所などを変更したときの下位条件の扱いを統一する。候補から消えた選択を解除する処理と、適用できない条件を入力値だけ保持する処理を分け、表示できない選択値が検索に残ることを防ぐ。

不一致を知らせる警告、解除通知、確認ダイアログは追加しない。

### 1.2 用語定義

| 用語 | 定義 |
|------|------|
| 上位条件 | 下位項目の候補または適用可否を決める条件。バージョン、場所、遭遇種別など |
| 候補依存の選択 | 現在の上位条件から取得した候補の中から選ぶ値。場所、固定個体、種族、配達カードなど |
| 適用可否 | その条件を現在の生成・検索処理に使用できるか。候補に選択値が存在するかとは別に判定する |
| 入力状態 | フォーム・ストアが保持する利用者の入力値 |
| 適用条件 | 入力状態から適用できない項目を除外し、候補との整合性を確認した実行用の条件 |
| 候補確定 | 現在の上位条件に対応する候補の取得が正常終了した状態。読込中・取得失敗とは区別する |

### 1.3 背景・問題

現行実装では `pokemon-params-form.tsx` がバージョン・遭遇種別・場所に応じて候補とスロットを再取得するが、種族フィルターは独立した入力状態として保持される。`normalizePokemonSearchFilter` も種族 ID を現在の候補と照合しない。

例えば B2 の電気石の洞穴 1F で選べるノズパス（種族 ID 299）は、B の同じ場所には出現しない。B2 から B に変更すると候補から消えるが、種族フィルターに ID が残り、該当しない検索条件が実行され得る。場所変更でも同じ構造の問題がある。

場所・固定個体の選択値も、バージョン変更後の候補との照合が不足している。古いスロットの実行は `hasCurrentEncounterSlots` で防いでいるが、選択値自体の整合性とは別の対策である。

配達員では ROM 条件に合わないカード ID を保持し、選び直しを要求する表示が存在する。こちらも候補から消えた選択として同じ規則に合わせる。

以上はコード・遭遇データの調査結果であり、この仕様作成時点でブラウザによる再現確認は未実施。

### 1.4 期待効果

| 項目 | 期待効果 |
|------|----------|
| 候補変更 | 新しい候補に存在しない選択だけが解除され、共通する選択は残る |
| 入力保持 | 一時的に適用できない項目の入力は、再び適用可能になれば利用できる |
| 実行整合性 | 表示候補に存在しない選択が、検索・一覧生成の条件に混入しない |
| 操作 | 追加の通知や確認操作を要求しない |

### 1.5 着手条件

本仕様のレビュー後に実装する。現時点では仕様書作成のみとし、アプリケーションコード、翻訳、永続化形式は変更しない。

関連仕様は `spec/agent/complete/local_122/CONTEXTUAL_SEARCH_FILTERS.md`。同仕様の「適用できない入力は保持する」方針は継承する。ただし、候補依存の選択を入力状態に残したまま適用条件だけで除外する方針は、本仕様の「確定候補から消えた選択は入力状態から解除する」に置き換える。

## 3. 設計方針

### 3.1 条件の分類

| 状態 | 入力状態 | 適用条件 |
|------|----------|----------|
| 適用可能で、確定候補に存在する選択 | 保持 | 使用する |
| 適用可能だが、確定候補から消えた選択 | 単一選択は解除。複数選択は候補との積集合に更新 | 残った選択だけを使用する |
| 項目・条件が適用不可 | 保持 | 除外する |
| 指定可能だが、結果が得られない絞り込み | 保持 | 使用する |
| 候補の読込中・取得失敗 | 保持 | 古い候補を使って実行しない |

種族フィルターが使える場所同士の移動では、現在地の種族候補との積集合を取る。固定個体など種族フィルター自体を使わない条件への移動では、種族の入力を保持して適用条件から除外する。野生に戻った後、取得した候補で改めて照合する。

レベル範囲、性格などは「その場所で結果が得られるか」を理由に変更しない。例えば出現レベルが 10–20 の場所に対するレベル指定 30–40 は、そのまま有効な絞り込みとして扱う。不一致表示も追加しない。

### 3.2 責務と変更範囲

候補取得とその取得状態は既存の機能別フック・フォームが管理する。選択整合の計算は純粋関数に分離し、検索と一覧生成で共用する。フォームの候補表示だけを修正せず、保持する入力状態と実行境界まで整合させる。

汎用の依存関係管理機構、新しいグローバルストア、Rust/WASM の変更は導入しない。DS 設定の既存の補正処理や、手動入力した Timer0 等の保持方針も変更しない。

検索件数見積もりへのレベル条件の追加、実際の出現個体を用いた新たな絞り込み可否判定、対応する遭遇種別の拡張は対象外。

## 4. 実装仕様

### 4.1 依存関係ごとの処理

| 上位条件 | 下位条件 | 処理 |
|----------|----------|------|
| バージョン・遭遇種別 | 場所 | 現在の候補に存在すれば保持。存在しなければ未選択にする |
| バージョン・遭遇種別 | 固定個体 | 現在の候補に存在すれば保持。存在しなければ未選択にする |
| バージョン・遭遇種別・場所 | 野生の種族フィルター | 現在地の種族候補との積集合を入力状態へ反映する |
| バージョン・リージョンから決まる配布言語 | 配達カード | 現在のカード候補に存在すれば保持。存在しなければ未選択にする |
| 遭遇種別・生成対象 | 種族・レベル・性別・特性・色違い等の適用可否 | 適用不可の条件は入力を保持して実行から除外する |
| 配達カードの固定設定 | 性格・性別・特性・色違い等 | カードにより指定不可となる条件は入力を保持して実行から除外する |
| タマゴの親条件・NPC 考慮 | 隠れ特性・猶予フレーム等 | 既存の適用可否による除外と入力保持を維持する |
| フィルター有効切替・個体値／実数値モード | フィルター全体・対応する範囲入力 | 入力を保持し、現在有効な条件だけを適用する |

野生の候補は現在のデータ構造に従ってバージョン・遭遇種別・場所で決まる。リージョン変更を理由に野生の選択を一律解除しない。

遭遇結果種別や隠れ特性など、既存の正規化で適用可否を判定している条件は、その保持規則を維持する。今回の候補削除規則は、データから取得する場所・固定個体・種族・カードの選択に適用する。

### 4.2 選択の解除と保持

単一選択の無効値は、そのフォームで定義された未選択値に戻す。候補の先頭など別の値へ自動で置き換えない。固定個体の候補取得時に先頭を選ぶ現行処理も、解除直後や再読込時に自動選択を起こさないようにする。

複数種族の選択は元の順序を保って候補との積集合を取る。全件が消えた場合は種族の指定なしとし、適用条件の `species_ids` は `undefined` にする。これは検索対象を広げる変更となるが、解除確認は追加しない。既存の結果件数警告はそのまま使用する。

候補外として解除した値は、以前のバージョンや場所に戻っても復元しない。項目自体が適用不可だったため保持した値とは区別する。

フィルター全体が無効でも、親条件と種族候補が確定し種族指定を利用できる場面では候補との照合を行う。再度フィルターを有効にしたときに候補外の選択を復活させない。

場所など必須の親選択が未設定なら、子の候補が確定したとは扱わない。種族入力は保持して適用せず、有効な場所の選択と候補取得後に照合する。親の候補が正常取得でき、その親選択自体が候補から消えた場合は親を解除する。

### 4.3 非同期取得と更新順序

候補には取得対象を識別するキーと状態を持たせる。未取得、読込中、正常終了、失敗を区別し、単なる空配列を解除の根拠にしない。正常終了した空の候補集合は、候補なしとして扱う。

上位条件変更後は、場所または固定個体の候補を確定し、有効な選択に対応するスロット・種族候補を取得してから種族入力を照合する。古い場所・固定個体を用いて取得した結果を、現在の候補として公開しない。

取得結果の反映時は、取得キーが現在の条件と一致することを確認する。古い非同期処理の完了や失敗が、新しい候補・選択を上書きしないようにする。既存のキャンセル処理とスロットのキー照合は維持する。

選択の整合には反映時点の最新入力を用いる。読込開始時に捕捉した選択値で、読込中の利用者の変更を上書きしない。変更不要ならストアを書き換えず、更新の循環を防ぐ。

カード ID を解除するときは、それに対応する解決済み選択も無効化する。保存済みのカード定義や別画面から引き継いだ選択があっても、現在の ROM 条件で利用できないカードを実行可能にしない。取得失敗では選択を解除せず、既存の取得エラーとして扱う。

### 4.4 表示・検証・実行

候補外の選択を通常の未選択状態へ戻し、解除通知や不一致表示は追加しない。配達員の「利用できないカード ID を保持して選び直しを要求する」表示は、この経路では使用しない。必須項目の未選択表示、取得エラー、既存の入力検証は維持する。

表示、検証、見積もりに渡すフィルター、実行リクエストは、同じ現在条件を基準にする。整合処理前の一時的な描画状態から候補外の条件が送信されないよう、実行境界でも現在の候補との照合を行う。候補未確定・親未選択では、古いスロットやカードを使って実行しない。

既存の見積もりが対応していない条件を、この変更によって対応済みとはしない。今回の変更は適用条件の統一であり、見積もりの計算精度改善ではない。

既に実行中の処理、確認ダイアログ用に確定したリクエスト、結果に紐づく生成条件は書き換えない。以後のフォーム入力と、既存のスナップショットを区別する。

### 4.5 復元と画面切替

永続化されたフォームの復元時と画面再表示時も、現在の上位条件に対応する候補が確定してから照合する。非表示の画面を常時更新する仕組みは必須としないが、再表示後の実行前には整合していることを保証する。

入力の永続化形式は原則変更しない。候補の取得状態・取得キーは永続化しない。形式変更が必要になった場合は、公開済みストアの移行規約に従い別途変更内容を明記する。

### 4.6 性能要件

| 項目 | 要件 |
|------|------|
| 選択照合 | 候補を集合化し、候補数と選択数に対して線形で処理する |
| データ取得 | 既存の候補取得結果を再利用し、照合だけのための重複取得を追加しない |
| 計算処理 | 実際の出現個体の生成、追加 WASM 呼び出し、検索の試行を行わない |
| 状態更新 | 選択が変わらなければ更新しない |

## 5. テスト方針

| 分類 | 対象 | 検証内容 |
|------|------|----------|
| 単体 | 単一選択 | 共通候補は保持し、候補外は未選択。代替値を選ばない |
| 単体 | 複数選択 | 一部消失は積集合、全件消失は指定なし。順序を保持する |
| 単体 | 適用可否 | 適用不可では入力を保持し適用条件から除外する |
| コンポーネント | B2 → B | 電気石の洞穴 1F のノズパスが解除され、共通種族は保持される |
| コンポーネント | 場所変更 | 別の場所でも同じ種族照合が行われる。元の場所に戻っても解除済み選択は復元しない |
| コンポーネント | 場所・固定個体 | バージョン変更後に候補外の選択を解除し、スロットは実行不可。共通選択は保持する |
| コンポーネント | 野生 → 固定 → 野生 | 固定では種族入力を保持・除外し、野生に戻ると現在候補で照合する |
| コンポーネント | 親未選択 | 一時的な空の種族候補で保持値を消さず、選択・取得後に照合する |
| コンポーネント | 非同期 | 読込中・失敗では解除しない。正常終了した空候補とは区別する |
| コンポーネント | 競合 | A → B → A の変更、完了順逆転、読込中の選択変更でも最新入力だけを反映する |
| コンポーネント | 配達カード | ROM バージョン・リージョン変更で候補外 ID と解決済み選択を解除し、共通カードは保持する |
| コンポーネント | 配達カード取得失敗 | 選択を保持し実行を防ぐ。解除通知・不一致表示を新設しない |
| 回帰 | 任意の絞り込み | 出現範囲と交差しないレベル範囲を保持し、不一致表示を出さない |
| 回帰 | 既存の正規化 | NPC 考慮、隠れ特性、遭遇結果種別、カード固定値、個体値／実数値切替の保持・除外を維持する |
| 回帰 | フィルター無効 | 無効中も確定候補外の種族を解除し、再有効化時に復活しない |
| 回帰 | 保存状態・画面切替 | 古い選択の復元後も、現在候補が確定した段階で整合する |
| 回帰 | 実行経路 | 検索・一覧生成双方で候補外の条件を送らず、見積もりと実行で同じ適用条件を用いる |
| 回帰 | 実行済み条件 | フォーム変更が実行中・確認待ちのリクエストや既存結果を書き換えない |

実装後は関連する単体・コンポーネントテスト、型チェック、Lint を実行する。ブラウザでは Pokémon 検索・一覧生成、配達員検索・一覧生成の各画面で、バージョン・場所・リージョン変更を確認する。

検証結果: 未実行（仕様書のみの変更）。
