# 対象に応じた検索フィルターと条件の有効化 仕様書

## 1. 概要

### 1.1 目的

既存の検索・生成フォームで、次の振る舞いを実現する。

1. 対象に対して意味のない項目・選択肢を表示しない。
2. 非表示・無効の条件を検索へ送らない。
3. 範囲条件を、入力値を保持したまま個別に有効／無効にできる。

ポケモン一覧・ポケモン検索・タマゴ一覧・タマゴ検索・MT Seed検索にある既存条件を対象とし、各画面で該当する箇所を変更する。下限のみを指定する条件も範囲条件に含める。

### 1.2 用語定義

| 用語 | 定義 |
|------|------|
| 対象条件 | ROM、エンカウント種別、選択済みスロット、孵化設定など、生成する個体を決める入力 |
| 入力状態 | ユーザが入力した値と有効フラグ。非表示・無効時も保持する |
| 適用条件 | 入力状態を対象条件に照らして正規化し、検証・見積もり・WASMへ渡す値 |
| 選択肢 | 各条件で選択できる値。対象による制限は§4の項目別規則に従う |
| 適用不可 | §4の規則で非表示・無効とする条件、またはその画面の検索APIが扱わない条件 |
| 探索範囲 | 日時、Timer0/VCount、消費数など、探索する組み合わせや位置を定める入力 |

### 1.4 期待効果

| 項目 | 受け入れ条件 |
|------|--------------|
| 不要な入力の非表示 | §4の経路・項目別規則に従い、種族・レベル等の項目と夢特性等の選択肢を非表示にする |
| 非表示・無効条件の適用除外 | 別項目の編集・全体トグル操作・保存済み設定の復元後も、該当条件を要求へ含めない |
| 範囲条件の入力保持 | 条件をOFF→ON、対象をA→B→Aと戻した際に以前の範囲を復元できる |

### 1.5 着手条件

表示・適用の判定には、現在の対象選択と一致する生成パラメータを使う。対象スロットが未確定の場合の扱いは§4.6に従う。

関連仕様: `spec/agent/complete/local_118/POKEMON_SEARCH.md`、`spec/agent/complete/local_120/POKEMON_GENERATION_PIPELINE.md`。配置・責務は `spec/agent/architecture/frontend-structure.md` に従う。

## 3. 設計方針

### 3.1 入力状態と適用条件を分ける

入力値を保持する状態と、検索へ渡す条件を区別する。非表示・無効化のために適用条件から外す際も、保持した入力値は消さない。

既存のフォーム・Storeを使い、範囲値と有効状態を保持するために必要な状態だけを追加する。状態管理方式の統一やフォーム全体の再構成を前提にしない。

適用条件は、対象が取得済みで、項目が適用可能で、有効フラグがONの場合にだけ構築する。既存のフィルター全体トグルは一覧2画面で維持し、OFF時は全条件を外す。折りたたみは表示状態だけであり、ONの条件を解除しない。

### 3.2 経路・項目別に判定する

種族・レベルは生成経路で表示を決める。性別は野生では常時表示し、固定・徘徊では選択対象の性別比から表示を決める。野生の性別候補の集計や、全属性の候補数を計算して一律に非表示にする仕組みは設けない。

色違いブロックなど対象固有の値が必要な項目だけ、選択中の生成パラメータを参照する。検索結果のサンプリングや、種族の絞り込みに連動した候補縮小は行わない。

### 3.3 項目と選択肢を区別する

種族・レベルは項目全体、通常のポケモンの特性スロットは夢特性の選択肢だけを非表示にする。隠し穴では特性スロットの絞り込み自体を無効化する。非表示・無効となった条件の入力値は保持し、適用条件から外す。

## 4. 実装仕様

### 4.1 ポケモンの表示規則

| 条件 | 表示規則 | 非表示・無効時の適用値 |
|------|----------------|----------------|
| 種族 | 野生経路では表示。固定・徘徊・隠し穴では非表示 | `species_ids=undefined` |
| レベル | 野生経路では表示。固定・徘徊では非表示。隠し穴は範囲生成の経路として表示 | `level_range=undefined` |
| 性別 | 野生・隠し穴は表示。固定・徘徊は選択対象が性別不明・♂限定・♀限定なら非表示、♂♀が出るなら表示。表示時は既存の選択肢を維持 | `gender=undefined` |
| 特性スロット | 野生・固定・徘徊は1・2を表示し、夢特性を選択肢から外す。隠し穴では項目を非表示にして絞り込みを無効化 | 夢特性の保持値、および隠し穴の特性条件は `ability_slot=undefined` |
| 色違い | 固定生成経路で有効な `shiny_locked` が対象全体に適用されるなら非表示。それ以外は既存の色違い選択肢を表示 | `shiny=undefined` |
| 性格 | シンクロ指定だけでは固定されないため表示を維持 | 条件なしの場合のみ `natures=undefined` |

| 経路の分類 | `EncounterType` |
|------------|-----------------|
| 野生 | `Normal`、`ShakingGrass`、`DustCloud`、`PokemonShadow`、`Surfing`、`SurfingBubble`、`Fishing`、`FishingBubble` |
| 固定 | `StaticSymbol`、`StaticStarter`、`StaticFossil`、`StaticEvent` |
| 徘徊 | `Roamer` |
| 隠し穴 | `HiddenGrotto` |

野生では、選択した場所が1種族・単一レベルであっても種族・レベル入力を表示する。固定・徘徊では候補一覧の件数にかかわらず非表示にする。

性別は、固定・徘徊の選択対象の `gender_ratio` が `Genderless`・`MaleOnly`・`FemaleOnly` の場合だけ項目を非表示にする。ヒードランのように♂♀が出る対象では表示する。野生は出現対象の性別構成や種族フィルターによらず表示し、候補を集計しない。表示時の選択肢は「指定なし・♂・♀・性別不明」を維持する。表示中の指定が対象と一致しない場合は0件とし、非表示にした場合は保持値を消さず適用条件から除外する。

`src/data/encounters/static/v1/B/StaticSymbol.json` のビクティニは種族・レベル・性別・色違いを非表示にする。コバルオンは種族・レベル・性別を非表示にし、色違いは表示する。特性名の数を使ってスロット1・2を統合しない。

隠し穴の専用関数はレベルを範囲生成するが、共通生成器への接続状況は§4.8のとおり。表示規則の定義を理由に非対応の検索を有効にしない。

### 4.2 ポケモン一覧固有の条件

| 条件 | 適用可能な対象 |
|------|----------------|
| 持ち物スロット | 全経路で項目を非表示とし、適用条件は常に `held_item_slots=undefined` |
| エンカウント結果 | `DustCloud`・`PokemonShadow` は `PokemonOnly`・`ItemOnly`、`Fishing` は `PokemonOnly`。それぞれ「指定なし」を含む |
| 特殊エンカウント発生 | `ShakingGrass`・`DustCloud`・`SurfingBubble`・`FishingBubble`・`PokemonShadow`。既存の「発生した場合のみ」を維持 |

持ち物判定の対象経路と `VeryRare` の成立条件には疑義があるため、持ち物スロット欄全体を非表示にする。保存済みの指定があっても、初回復元・別項目の編集・全体トグル操作・経路変更を通じて要求へ含めない。生成処理の調査・修正は別件とする（`spec/agent/notes/dev-journal.md` の「持ち物判定の対象経路と VeryRare の成立条件」）。

適用するエンカウント結果を先に決める。`ItemOnly` の場合、個体属性（種族・レベル・性格・性別・特性・色違い・個体値・めざパ・実数値・ポケモンの持ち物）をすべて非表示・不適用とする。特殊発生条件は維持できる。`RawPokemonData::not_pokemon` の仮値へ個体条件を照合させない。

結果が「指定なし」の場合は個体条件を利用できる既存の照合規則を維持する。ポケモン検索APIは常に `PokemonOnly` を適用するため、エンカウント結果等の一覧固有入力は新設しない。

### 4.3 タマゴの条件

| 条件 | 判定 |
|------|------|
| 性別 | 孵化設定によらず表示し、既存の選択肢を維持する。固定性別・`nidoran_flag` に基づく表示変更や条件の自動解除は行わない |
| 夢特性 | `uses_ditto=false` かつ `female_ability_slot='Hidden'` の場合だけ候補に含める。1・2は残す |
| 性格 | `everstone={ Fixed: ... }` でも現在の生成処理には継承失敗分岐があるため、固定と判断しない |
| 色違い | 国際孵化は再抽選回数の変更であり、固定属性ではない。条件を表示する |
| 猶予フレーム下限 | `consider_npc=true` の場合だけ表示・適用する |
| 実数値 | タマゴ一覧で生成へ渡す `species_id` が指定済みの場合に表示。未指定では `Stats::UNKNOWN` となり絞り込めないため非表示・不適用 |
| 個体値・めざパ | 個体値不明が含まれる可能性だけで非表示にしない。遺伝抽選によって既知値だけの個体が生成される場合がある |

根拠は `wasm-pkg/src/generation/flows/egg.rs`、`generation/algorithm/nature.rs`、`generation/flows/generator/egg.rs`、`generation/flows/types.rs`。タマゴ検索には実数値入力を新設しない。ニドラン・イルミーゼの性別と出力種族の変換を維持する。

`IvFilter` は不明値32を任意範囲なら通し、特定範囲なら落とす。不明個体値を含む結果のめざパ照合はスキップする。`StatsFilter` は実数値が不明なら条件値によらず通す。この既存契約は変更せず、めざパ条件がすべての不明個体へ厳密に適用されるかのような説明をしない。

### 4.4 範囲条件の切り替え

| 条件 | 操作 | 無効時の適用条件 |
|------|--------------|----------------|
| レベル範囲 | min/maxを1組として有効／無効を切り替える | `undefined` |
| 個体値範囲 | H/A/B/C/D/S各行の「任意」チェック。チェックありで範囲指定を解除 | 当該能力を `[0,31]` にする |
| めざパ威力下限 | タイプ選択とは独立して有効／無効を切り替える | `hidden_power_min_power=undefined`。タイプ選択は維持 |
| 猶予フレーム下限 | 下限指定の有効／無効を切り替える | `min_margin_frames=undefined` |

入力値と適用の有無を独立に保持する。条件無効中は数値欄を編集不可とし、再度有効にすると以前の値を使う。対象が適用不可の場合は項目全体を隠すが、同じ入力状態を保持する。フォーム全体の折りたたみはこれらの切り替えとは別に扱う。

条件未指定の初期状態は範囲指定なしとする。個体値では「任意」にチェックし、それ以外の範囲条件では有効化をOFFにする。保持値の初期値はレベル `[1,100]`、各個体値 `[0,31]`、めざパ威力30、猶予フレーム0。既存の入力値がある場合はその値を使い、初期値で上書きしない。

個体値の全行が任意かつめざパ条件なしなら、任意型のAPIでは `iv=undefined` とする。`MtseedSearchContext.iv_filter` は必須のため、全能力 `[0,31]` を送る。全条件を解除したMT Seed検索も既存の件数見積もり・確認経路を通す。

個体値はタマゴ側の `IvRangeInput` の「任意」チェックに揃える。ポケモン一覧・MT Seed検索でも同じ配置と操作方向を使い、別の有効化スイッチを追加しない。「任意」にチェックすると数値欄を無効化し、チェックを外すと保持していた範囲へ戻す。例えば `[30,31]` → 任意 → 解除で `[30,31]` に戻る。現在の実装は解除時に `[0,31]` へ戻しているため、この復元部分を改修する。

タマゴ側の既存UIは任意を `[0,32]` で表す。適用条件へ変換する際は `[0,31]` に正規化し、MT Seed検索へ不明値用の32を渡さない。Rustの照合では `[0,31]` も不明値32を通すため、タマゴの任意条件の意味は変わらない。親個体値の「不明」は生成入力であり、変更しない。

実数値は完全一致条件なので、範囲の切り替え対象に含めない。入力・解除方法は既存のままとし、非表示時の適用除外だけを行う。

日時・Timer0/VCount・消費数の範囲は探索範囲なので、本仕様のOFF操作を付けない。MTオフセット、親個体値、先頭特性も生成入力として維持する。

### 4.5 入力状態から要求への変換

変換は次の順序で行い、同じ関数を画面表示・開始時処理で共有する。

1. ROM・対象選択と取得済みスロットが一致することを確認する。
2. 経路・項目別の表示規則と、一覧では適用するエンカウント結果を求める。
3. 全体トグル、項目の適用可否、表示モード、範囲指定の有無、表示する選択肢に基づき各条件を正規化する。
4. 適用条件を検証する。例えば無効な色違い条件を保持しているだけなら、ポケモン検索のTID/SID必須エラーを出さない。
5. 正規化済みの条件を含む要求を複製して固定し、件数見積もり・確認ダイアログ・Workerへの送信に同じ要求を使う。

非表示条件の除外は対象変更のeffectだけで行わず、別項目の編集、全体トグル操作、保存済み設定の復元、検索開始のいずれにも適用する。表示と要求作成で同じ適用可否の判定を使う。

選択肢を制限する項目では、複数選択は表示する選択肢との積集合、単一選択は選択肢内かで判定する。積集合が空なら条件なしとする。入力状態は変更しないため、元の対象へ戻れば元の選択が再適用される。性別は項目が表示されている間は選択肢と指定値を維持し、§4.1に従って項目を非表示にした場合だけ適用条件から除外する。

一覧2画面は既存の `statMode` による入力表示の切り替えを維持する。`stats` モードでは非表示の個体値・めざパ条件を除外し、`ivs` モードでは非表示の実数値条件を除外する。保持値は消さず、元のモードへ戻すと再適用する。新しい入力ブロックや、個体値・実数値の同時指定操作は追加しない。

数値条件はONの項目だけ既存の範囲検証へ渡す。適用可能なレベル範囲を対象レベルの範囲へ自動で狭めない。ユーザ指定が実際の候補と重ならない場合は、入力が見えている状態で0件になることを許容する。

結果表、詳細、CSVは実行時の結果・設定を参照し続ける。検索後の対象変更やトグル操作で既存結果を再フィルタリングしない。結果から一覧への転記・フォームリセット・永続化復元でも、次回の開始時には同じ正規化を必ず通す。

### 4.6 対象判定に使うスロット

色違いブロックや固定・徘徊の性別比の判定には、現在の選択対象と一致するスロットを使用し、固定カテゴリ全体の候補一覧は使わない。種族・レベルの表示は経路から判定する。野生の性別欄の表示にはスロットの集計を行わない。

取得中・未選択・取得失敗では、色違いブロック等の対象固有の判定を行わない。現在のROM・種別・場所・固定対象IDに対応するスロットが確定するまで検索開始を待つ。古い対象の取得結果を判定へ混ぜないために必要な受け渡し・開始条件だけを既存の取得経路に追加する。

### 4.7 入力保持・リセット

範囲値と有効状態を分け、OFF→ON、対象変更、表示モード変更で復元できるようにする。フォームのリセットは非表示・無効中の保持値も初期化する。全体トグル・折りたたみ・画面全体のリセットは既存の操作を維持する。

有効状態を持たない従来の保存値を読み込む際は、指定済みの範囲をON、未指定または任意の個体値範囲をOFFとして扱う。有効状態が保存されている場合はそれを使う。猶予フレームの0は指定値として扱う。個体値と実数値の値が両方保存されていても、表示モードに対応する条件だけを適用する。

全画面共通の新しいStore構造や保存期間は設けない。保持元の変更によって既存の保存形式に変更が必要な場合に限り、そのStoreの `version` と `migrate` を更新し、既存の入力値を引き継ぐ。

トグルと数値欄はラベルを関連付け、能力名・条件名を含むアクセシブル名を付ける。OFFの入力へフォーカスを移さない。検索中は対象・条件・トグルの変更を止める。未確定の数値入力から検索・OFF操作へ移る場合のblur確定順をテストする。翻訳更新は `i18n-catalog` スキルに従う。

### 4.8 本件で扱わない拡張

`HiddenGrotto` はポケモン日時検索で明示的に非対応。専用生成関数はあるが共通生成器の振り分けに接続されていない。夢特性対応を含む生成器の修正を本件へ混ぜず、非対応判定を維持する。JSONの `isHiddenAbility` だけから、現在の生成出力が夢特性固定だと推測しない。

ポケモン検索APIへ個体値・実数値・持ち物・特殊発生等の条件を追加しない。フィルターの新しい種類、未知個体値の厳密照合、検索件数見積もり式の精度改善、持ち物生成のゲーム仕様監査も対象外とする。

## 5. テスト方針

### 5.1 表示規則と適用条件のユニットテスト

| ケース | 期待する振る舞い |
|--------|------------------|
| 固定・徘徊と野生の切り替え | 固定・徘徊では種族・レベルを除外し、野生へ戻ると保持値を復元 |
| 野生で1種族・単一レベル、固定カテゴリに複数候補 | 候補数によらず経路別の表示を維持 |
| ビクティニとコバルオン | 色違いブロックのある前者だけ色違い条件を除外。性別は両方非表示・不適用 |
| ヒードランと性別不明・♂限定・♀限定の固定／徘徊対象の切り替え | ヒードランでは性別を表示。他の対象では非表示・不適用とし、戻ると保持値を再適用 |
| 野生で性別が1種類の場所、複数の性別が混在する場所、種族フィルターの変更 | 性別欄と既存の選択肢を常に表示し、指定値を自動解除しない |
| 野生・固定・徘徊と隠し穴 | 前者は夢特性の選択肢だけ除外、隠し穴は特性条件全体を除外。非対応検索は有効化しない |
| 全経路で持ち物条件を保持した設定を復元・更新 | 持ち物欄を常に非表示とし、保持値によらず `held_item_slots` を要求から除外 |
| 砂煙 `ItemOnly` → 釣り → 砂煙 | 釣りでは不適用、戻ると入力を復元。個体条件の除外も連動 |
| 夢特性の♀親、メタモン切り替え | メタモン使用時に夢特性条件を除外、戻れば復元 |
| タマゴの固定性別・`nidoran_flag` の切り替え | 性別の表示・選択肢・保持値を変更しない |
| NPC考慮なし、下限0または正数を保持 | どちらも猶予条件を除外。考慮ありでは0を有効値として扱う |
| 個体値の全行を任意、めざパだけ指定 | 能力範囲は `[0,31]`、めざパ条件だけ残る。MT Seed検索へ32を送らない |
| 従来の保存値に指定済みの範囲がある | 範囲を引き継ぎ、表示可能・有効な条件だけを適用する |

### 5.2 コンポーネント・ページテスト

| 操作 | 確認内容 |
|------|----------|
| 範囲入力→OFF→ON | 入力値復元、OFF中の適用なし、他の条件は維持 |
| 個体値 `[30,31]` →「任意」にチェック→解除 | ポケモン一覧・タマゴ一覧・タマゴ検索・MT Seed検索で同じ操作になり、解除後は `[30,31]` に戻る |
| 対象変更→別項目編集→開始 | 隠した条件が再送されない。初回マウント・再読み込みでも同じ |
| フィルター全体OFF→ON | 保持値は復元し、非表示の項目と個別にOFFの範囲は除外したままにする |
| 非表示の値を残してリセット | 対象を戻しても古い値が復活しない |
| 実数値／個体値表示を切り替えて開始 | 非表示の側の条件を要求から除外する。元の表示へ戻すと保持値を再適用する |
| 色違いブロック対象、未設定TID/SID | 保持中の色違い条件だけで開始を妨げない |
| 数値編集中に開始、OFF、リセット | 最新の確定値を使用し、blurで古い状態を再送しない |
| 検索確認中・実行後に対象・条件変更 | 確認・送信は保存済み要求を使用し、既存結果とCSVの個体集合を変えない |
| 対象A取得中にBへ変更、Aが後着 | Bのスロットを上書きしない。未確定状態で開始不可 |
| MT Seedの全行を任意 | 全範囲条件を用いた見積もり・既存の大量結果確認を通る |

### 5.3 WASM連携と検証項目

既存の `src/test/integration/pokemon-datetime-search.test.ts`、`egg-datetime-search.test.ts` と生成系テストへ、正規化した要求の結果が不要条件を除いた基準要求と一致するケースを追加する。NPC猶予・色違いブロック・不明個体値・レベルの生成経路を代表ケースにする。持ち物条件は保存値の有無によらず要求から除外され、未指定の要求と結果が一致することを確認する。Workerへ渡す要求も検証し、フォームの表示テストだけで完了にしない。

実装後は変更範囲のユニット／コンポーネント／統合テスト、TypeScript型検査、Lint、フォーマット検査を行う。ブラウザで5画面の対象変更・OFF/ON・再読み込み・リセットを確認する。
